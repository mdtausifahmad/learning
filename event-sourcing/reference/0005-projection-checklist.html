Projection Checklist

Compressed from Lesson 05•Print-friendly
One line

A projection is a fold over the global log into a database. Delivery is at-least-once; exactly-once effect comes from an idempotent, atomic apply.

The three properties

PropertyHow
IdempotentPer-row guard WHERE last_position < :pos; UPSERT; or dedupe on event_id
CheckpointedSave globalPosition in the same transaction as the read-model write (when same DB)
RebuildableCan start from 0 into a fresh table; nothing else writes to the read model

Review checklist

  • Projection name is versioned (orders-summary-v2); so is its table.
  • Read-model write + checkpoint in one tx — or, across stores, a position/version guard on every write.
  • default branch ignores unknown events but still advances the checkpoint.
  • Handler is a pure function of the log: no calls to other services or live tables.
  • Cross-stream joins consume both streams’ events and keep a local lookup table.
  • Aggregations store inputs (or are commutative); no “closed” totals that refunds can’t reach.
  • Exactly one active instance per projection (or per partition).
  • Failures retry with backoff, then park + alert. Never log-and-skip.
  • Catch-up uses batches; checkpoint once per batch, same tx.
  • Metrics: lag (positions & seconds), state, parked count, rebuild duration.

Lifecycle

start ─▶ CatchingUp ─(head)─▶ Live ─(error)─▶ Failed ─(retry ok)─▶ Live
                                 │                 └─(poison)─▶ Parked ⚠ alert
                                 └─(deploy v2)─▶ Rebuilding ─(caught up, swap)─▶ Live

Projection types

TypeWatch out for
Per-entity (document)Easiest; parallelise by stream id
List / searchIndexes / search index mapping
AggregatingNon-commutative ops; prefer storing inputs
Cross-stream joinMust consume e.g. CustomerRenamed; local lookup
In-memoryRebuilt on startup; fast catch-up or snapshot
Live / ad-hocTemporary; throw away
Integration publisherOutput is Kafka; consumers dedupe on eventId

Core SQL

UPDATE rm_account_balance SET balance = balance + :amt, last_position = :pos
 WHERE account_id = :id AND last_position < :pos;            -- guard

INSERT INTO projection_checkpoints (name, position) VALUES (:name, :pos)
ON CONFLICT (name) DO UPDATE SET position = EXCLUDED.position;  -- same tx
