Event Sourcing · Reference 12

Anti-Patterns & Failure Modes

Compressed from Lesson 16•Print-friendly
Anti-patternSymptomRemedy
ES everywhereEvery microservice event-sourced “for consistency”; simple CRUD domains drowning in projectionsApply per bounded context, only where history has business value
CRUD events (EntityUpdated, FieldChanged)Events look like diffs; no business intentModel domain facts; run Event Storming with domain experts
Event store as public integration busOther teams consume your internal events; you can’t refactorSeparate domain vs integration events
Fat aggregate stateAggregate state = read model; slow rehydration; huge snapshotsKeep only invariant-relevant state; move the rest to projections
God aggregate / long streamsConcurrency conflicts, millions of events per streamRe-draw boundaries; close the books
Querying the event store for business readsSELECT … FROM events WHERE data->>'customerId' = … in request pathsBuild a projection
Side effects in evolveEmails re-sent on every replaySide effects only in reactors/subscriptions, never in state application
Non-deterministic evolveUses now(), random, external lookups → replay gives different statePut all needed data in the event at decision time
Dual write to brokerLost or phantom messagesPublish from the event store via subscription
Ignoring the gap problemProjections silently skip events under loadCommit-ordered reads (tx-id visibility filter)
No versioning strategyFirst rename of a field breaks replay in prodUpcasters + historical-event CI corpus
Editing events in place to “fix” dataAudit trail destroyed; projections divergeCompensating events; copy-transform only as governed migration
Projection writes from multiple placesCan’t rebuild deterministicallyRead models are written only by their projection
Synchronous everythingInline projections for every view → write latency explodesInline only for the 1–2 views that need it
Also flag in review

PII in stream ids or metadata · fabricated history in migrations (use AccountImported) · CDC change events called “event sourcing” · snapshots added before measuring · no exit plan in the ADR.
