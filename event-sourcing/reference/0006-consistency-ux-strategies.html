Read-your-writes in Java

public OrderView getOrder(String id, Optional<Long> minPosition) {
    minPosition.ifPresent(p -> checkpoints.awaitAtLeast(activeProjection("rm_orders"), p, Duration.ofSeconds(2)));
    return repo.findById(id).orElseThrow(NotFound::new);
}
  • Bound the wait; on timeout return data + a freshness flag (e.g. X-Read-Model-Fresh: false).
  • Resolve the projection behind the alias — don’t hard-code -v1.
  • Token is only valid if the poller can’t skip gaps (Lesson 08).

Blue/green rebuild

1. deploy orders-summary-v2 → own checkpoint (0), own table rm_orders_v2
2. catch up in background (v1 keeps serving)
3. verify: counts · EXCEPT diff · sampled spot checks · build indexes
4. BEGIN; DROP VIEW rm_orders; CREATE VIEW rm_orders AS SELECT * FROM rm_orders_v2; COMMIT;
   (OpenSearch: POST /_aliases with remove + add in one call)
5. stop v1; drop rm_orders_v1 after grace period

Rebuild speed

  • Batch writes (COPY, JDBC batch, bulk API); checkpoint per batch.
  • Defer secondary indexes until near head; create before swap.
  • Parallelise per-entity projections by hash(stream_id) % N, one checkpoint per partition.
  • Optional: UNLOGGED during catch-up, SET LOGGED before swap.
SLOs to publish

Freshness: p99 projection lag per read model (agreed with product). Rebuild time: slowest projection from zero. If it’s days, you’ve lost a core ES benefit.
