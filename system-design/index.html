Software design and architecture

System Design & Architecture at Scale

8 lessons · 8 reference sheets · 1 full Markdown guide•≈ 4–6 weeks part-time

Lead any open-ended design conversation with one repeatable method — requirements, high-level design, core components, scale it — and name the trade-off behind every choice. Each lesson is a single sitting, with quizzes and a “try it in your own system” task. Prefer one long read? The whole course is also in GUIDE.md (with Mermaid diagrams). See MISSION.md for the why.

For senior engineers aiming at Staff or Principal who can already build services but want to lead the design conversation. Eight lessons cover the mental models (scaling axes, CAP and consistency), the building blocks (data, caching, async, networking and APIs), the quantitative glue (estimation) and how to stay up when things fail. Everything hangs off one 4-step method: requirements & constraints → high-level design → core components → scale it and name the trade-offs. This is competency A1, the core technical skill, in the skills playbook.

Part I · Mental models

How systems grow and what breaks first: scaling axes, availability maths, CAP and consistency.

  1. Scalability Trade-off Axes
    Performance vs scalability, latency vs throughput, scale up vs out, the AKF cube and availability nines.
  2. CAP Theorem & Consistency Models
    CAP and PACELC, the consistency spectrum, client guarantees, N/W/R quorums and when you need consensus.

Part II · Building blocks

The parts you compose: data stores, caches, async pipelines, networks and API contracts.

  1. Databases & Data Modeling
    The cheapest-first scaling ladder, replication, sharding, SQL vs NoSQL, isolation levels, B-Tree vs LSM.
  2. Caching
    Cache layers, read and write patterns, eviction, invalidation, and fixes for stampede, hot keys, penetration.
  3. Asynchronism & Messaging
    Queues vs pub/sub, back-pressure, delivery semantics and idempotency, event sourcing, CDC and Kafka.
  4. Networking & API Design
    TCP/UDP, HTTP/1→3, REST vs gRPC vs GraphQL, L4/L7 load balancing, DNS, CDN and API design rules.

Part III · Quantitative glue

Estimate first, so the numbers pick the bottleneck and the architecture.

  1. Back-of-the-Envelope Estimation
    Powers of two, latency numbers, nines, and the users → QPS → storage → bandwidth → cache → servers method.

Part IV · Staying up

Contain failure: timeouts, retries, breakers, bulkheads, shedding and health checks.

  1. Resilience & Fault Tolerance Patterns
    Timeouts, retries with backoff and jitter, circuit breakers, bulkheads, degradation, shedding, probes.
