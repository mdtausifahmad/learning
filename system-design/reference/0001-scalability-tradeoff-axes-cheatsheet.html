Scalability Trade-off Axes

Compressed from Lesson 01•Print-friendly
Mindset

Scalability means adding resources buys proportional capacity, with no rewrite and no latency collapse. Quantify first, scale out stateless by default, and know exactly which component is the stateful bottleneck.

Diagnose before you scale

SymptomProblemLook for
Slow for a single userPerformanceThe code path, the query, the algorithm
Fast for one user, slow under loadScalabilityAnything whose cost grows super-linearly: a shared lock, a single DB, an O(n²) fan-out

Latency vs throughput

  • Latency — time for one operation. Quote p50 / p95 / p99 / p99.9, never just the average.
  • Throughput — operations per unit time. Goal: max throughput at acceptable latency.
  • Little’s Law — Concurrency = Throughput × Latency. Batching and queuing raise throughput but add latency.
  • Fan-out amplifies the tail — 100 calls per page at p99 = 1 s → 1 − 0.99100 ≈ 63% of pages hit a slow call.

The unlock is statelessness: push sessions to a shared store or a signed token, and any server can take any request. State then lives in stores you scale deliberately (Lesson 03).

Every synchronous hop costs availability. Add redundancy, remove hops, or make hops async. SLI = what you measure; SLO = internal target; SLA = contractual promise (looser than the SLO).

Review questions

  • What are the target QPS, data size and latency budget? (Lesson 07)
  • Is this a performance or a scalability problem? Which component grows super-linearly?
  • Are latency budgets and alerts set on p99, not the average?
  • Which component is stateful, and how does it scale?
  • Which AKF axis does the next 10× need?
  • What is the composed availability of this path, and which hop costs us a nine?
Traps
  • Premature scaling — building for 1B users at 1,000. Keep it boring until the numbers say otherwise.
  • Hidden single points of failure — one primary DB, one cache, one AZ: redundant on paper, series in practice.
  • Optimising the average while p99 melts under load.
  • Stateful app servers that block scale-out and make deploys and failover painful.
