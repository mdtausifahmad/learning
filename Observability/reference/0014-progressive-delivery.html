Progressive Delivery

Compressed from Lesson 13•Print-friendly
Why it matters

A majority of incidents come from binary/config pushes. Make change safe: separate deploy (dark) from release (exposed) with feature flags.

Canary

Build → Deploy dark → Canary (small %) → SLIs healthy?
                                          ├─ yes → expand → full
                                          └─ no  → rollback / flag off
  • Canary = partial, time-limited deploy + evaluation. Canary vs control on real traffic (A/B for safety).
  • Compare golden signals (errors, latency); widen internal → 1% → 10% → 50% → 100% with bake time.
  • Blast radius = canary size. Gate promotion on SLO / error budget.

Feature flags

TypeUse · owner
Releasehide half-built feature · dev · short-lived
ExperimentA/B for impact · product
Opskill switch under load (= graceful degradation) · ops

Expose current flag state · human-readable descriptions · delete flag debt.

Rollback checklist

  • Tested & automated — not improvised.
  • Schema-safe — old code works with new schema.
  • Mixed-version safe — old + new coexist during rollout.
  • Small deployments → cheap rollback. Irreversible change → extra safeguards.
Expand / contract migrations

Expand (add new, both work) → migrate → contract (remove old). Old and new coexist at every step, so canary and rollback stay safe.
