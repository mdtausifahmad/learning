Graceful Degradation & the Thundering Herd

Compressed from Lesson 12•Print-friendly

Graceful degradation — do less, stay up

Reduce the work per request (vs load shedding, which drops requests): cached subset, faster ranking, stale data, drop non-critical features. Preserve the critical journey — decide which features are droppable before the incident.

Caveat

Degraded mode is your least-tested code. Exercise it regularly, alert when it engages, keep it simple, and give it a kill switch. “The code path you never use is the one that doesn’t work.”

The herd family

Latency cache vs capacity cache

Latency cache: survives an empty cache (just faster). Capacity cache: a hard dependency — can’t serve normal load cold, so a restart = outage. Know which you have.

Taming techniques

  • Jitter / stagger retry waits, cache TTLs, cron times, reconnects.
  • Coalesce (single-flight): one request recomputes, the rest wait.
  • Refresh early / serve-stale-while-revalidate so expiry never misses.
  • Gradual warmup / slow start: ramp traffic to warm caches; keep clusters warm.
  • Rate limit / token bucket to smooth bursts.
  • Push config gradually, off-peak — an all-at-once rollout is a self-made herd.
The principle

Herds happen because independent things became correlated. Every fix is one of three: add randomness (jitter), dedupe (coalesce), or ramp (slow start).
