Choosing SLIs — Menu & Method

Compressed from Lesson 02•Print-friendly

The shape (use it for every SLI)

        good events
SLI = ─────────────── × 100%      valid = events you're accountable for
        valid events               good  = valid events that met the bar
Why this shape

Ranges 0–100% · composes with error budget (100% − SLO) · uniform numerator/denominator/threshold so one set of tooling serves all SLIs.

The SLI menu — pick the type by component

ComponentSLI typeMeasures
Request-driven
(API, web)		AvailabilityProportion of requests that succeed.
LatencyProportion faster than a threshold.
QualityProportion served un-degraded under stress.
Pipeline
(batch, stream)		FreshnessProportion of data newer than a threshold.
CorrectnessProportion of records that produce the right output.
CoverageProportion of valid input actually processed.
StorageDurabilityProportion of data that survives / is retrievable.

Request-driven services (most of yours): start with Availability + Latency. Keep to ≤5 SLI types total.

Specification vs. implementation

  • Specification = the user outcome that matters, no method. “ratio of loads < 100 ms”.
  • Implementation = spec + how you measure it.
  • One spec → many implementations, judged on quality · coverage · cost.

Where to measure (closest wins)

  • Client telemetry — most truthful, costliest.
  • Load balancer — sees requests the server never did.
  • Server logs — cheap; misses requests that never arrived.
  • Rule: measure as close to the user as you can afford.
Two traps

1. Infra proxies. CPU, memory, uptime, pod counts can be green while users fail. Measure the experience.   2. Averages. The mean hides the tail. Use ratios past a threshold, and two thresholds for typical + tail (e.g. 90% < 100 ms and 99% < 400 ms).

Starter recipe

  1. Pick one application.
  2. Define who the users are.
  3. List their critical journeys.
  4. Sketch architecture; classify components (request / pipeline / storage).
  5. Choose ≤5 SLI types for the most critical functionality; ship one, iterate.

Prometheus shapes
