The Saga Pattern — Cheat Sheet

Compressed from Lesson 15•Print-friendly

What it is

Core

A transaction across services = a sequence of local transactions, each publishing an event/command that triggers the next. On failure, run compensating transactions to undo the earlier steps. No 2PC, no distributed lock.

Key ideas

  • Compensation ≠ rollback: a new transaction that semantically undoes a committed one (ReserveInventory → ReleaseInventory).
  • Coordination (L13): choreography (events, decentralized) or orchestration (central state machine, commands).
  • Pivot transaction: compensatable steps → pivot (commit point) → retriable steps. Compensate before; retry-forward after.

The hard truths (ACID lost)

No isolation

Concurrent sagas can cause anomalies. Countermeasure: a semantic lock — a PENDING state flag. Also: commutative updates, re-read, versioning.

  • No automatic rollback → design (and test!) every compensation.
  • Eventual consistency → design the UX for "processing…".

Building blocks

  • Each step commits + publishes via the outbox (L14).
  • Every handler is idempotent (L08) — redelivery + re-run.
  • A correlation/saga id ties steps, ordering, and replies.
  • Consider a workflow engine (Temporal, Step Functions, Camunda).
  • Don't saga what fits in one service — keep it a local ACID transaction.
