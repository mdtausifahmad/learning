Transactional Outbox — Cheat Sheet

Compressed from Lesson 14•Print-friendly

The problem

Dual write

Update the DB and publish a message = two systems, no shared transaction. DB-then-crash = lost event. Publish-then-rollback = phantom event. @Transactional doesn't span the broker; 2PC/XA isn't viable.

The fix

Outbox

Insert the message into an OUTBOX table in the same local ACID transaction as the business change → atomic. A separate relay publishes it. Sent iff the DB commits.

@Transactional
fun pay(orderId: String) {
    orders.markPaid(orderId)                       // business change
    outbox.save(OutboxEvent(id=UUID(), "order.events", orderId, OrderPaid(orderId)))  // same tx
}

Relay: two ways

PollingCDC (log tailing)
HowSELECT unsent → publish → mark sentDebezium tails WAL/binlog → Kafka
ProsSimple, no extra infraLow latency, no polling load
ConsPoll lag + DB load; ORDER BY for orderMore infra; log coupling

Guarantees

  • ✓ Event published iff DB committed — no lost / phantom events.
  • ✓ Order preserved (ORDER BY per key / the log is ordered) — L09.
  • ⚠ At-least-once (relay may republish) → consumers must be idempotent (L08).
  • Outbox (reliable produce) + idempotent consumer (reliable consume) = effectively-once.
  • Prune sent rows so the table doesn't grow forever.
