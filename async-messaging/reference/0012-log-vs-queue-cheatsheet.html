Log vs Queue Brokers — Cheat Sheet

Compressed from Lesson 12•Print-friendly

The one question

Ask this, predict everything

Does reading delete the message?
Queue (RabbitMQ/SQS): yes — consume & delete. Log (Kafka/Pulsar): no — append & retain; consumers track offsets.

Everything follows

BehaviourLogQueue
Replay / rewindYes (seek offset)No (acked = gone)
Fan-outFree (offset per group)Copy per consumer
OrderingIntrinsic per partitionFragile
Consumer trackingOffsetPer-message ack state
ParallelismCapped by partitionsAdd consumers freely
DLQ / priority / TTLBuild it / noNative / yes

Inside

  • Log: append-only immutable segments (data + index), sequential I/O + zero-copy; retention by time/size; cleanup.policy=compact = latest value per key.
  • Queue: per-message delivery state; redelivery on nack / visibility-timeout; removed on ack; per-message priority/TTL/DLQ.

Choose

One-line test

Stream of events others may replay → LOG. Queue of tasks done once & discarded → QUEUE. (Events lean log; commands/tasks lean queue.)

Hybrids: Pulsar (log storage + queue subscriptions), Kinesis (log) vs SQS (queue), Redis Streams (log-shaped).

spring.kafka.consumer.auto-offset-reset = earliest   # replay from 0 (log only)
cleanup.policy = compact                             # changelog: latest per key
