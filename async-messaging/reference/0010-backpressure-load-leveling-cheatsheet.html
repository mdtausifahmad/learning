Async & Messaging · Reference 10

Backpressure & Load Leveling — Cheat Sheet

Compressed from Lesson 10•Print-friendly

Two ideas

Core

Load leveling: the buffer decouples arrival rate from processing rate — a spike becomes depth, not a stampede. Backpressure: how a slow consumer avoids being overwhelmed.

Pull vs push

Backpressure source
Pull (Kafka, SQS)Consumer fetches at its own pace → automatic; slow consumer just lags. The log is the buffer.
Push (RabbitMQ)Broker pushes → needs basic.qos prefetch (cap unacked per consumer). Prefetch 0 = infinite = danger.

The hard truth

Buffering ≠ capacity

Buffers absorb bursts, not sustained overload. Rising lag with no spike = under-provisioned → scale consumers (≤ partitions) or shed load. A bigger buffer only delays the wall.

Load shedding

  • Bound the buffer; when full, return 503 so clients back off + retry (exponential backoff).
  • Backpressure should propagate upstream to a polite "try again" — don't swallow overload into an unbounded queue.

Lag is the metric

  • Kafka consumer lag · SQS ApproximateNumberOfMessagesVisible · RabbitMQ queue depth.
  • Alert on it; autoscale on it (KEDA) — not on CPU.

Levers

# RabbitMQ (push)
spring.rabbitmq.listener.simple.prefetch = 20     # bound in-flight; never 0

# Kafka (pull)
consumer.max-poll-records = 200
consumer.properties.max.poll.interval.ms = 300000 # process the batch in time or get kicked
container.pause() / resume()                       # app-level backpressure
