Schema Evolution & Contracts — Cheat Sheet

Compressed from Lesson 16•Print-friendly

Why it's hard

Events are unforgiving contracts

Independent deploys (versions overlap) · retained logs replay old events (L12) · unknown pub/sub consumers. Both old and new schemas must interoperate.

Compatibility types

TypeMeansUpgrade first
Backward (default)New schema reads old dataConsumers
ForwardOld schema reads new dataProducers
FullBothEither
*_TransitiveAgainst ALL prior versions—

Golden rules

  • Add fields as optional, with a default. ✓
  • Never rename/remove a required field (deprecate). ✗
  • Never change a type (add a new field). ✗
  • Never reuse a field number/position (Protobuf). ✗
  • Be a tolerant reader — ignore unknown fields (free forward compat).

Formats & registry

  • Avro (built for evolution, reader/writer + defaults) · Protobuf (field numbers; BACKWARD_TRANSITIVE) · JSON (+ JSON Schema).
  • Schema Registry: stores schemas, enforces compatibility at register (fail the build), messages carry a schema ID.

Breaking change (unavoidable)

New topic / version field → dual-publish old+new → migrate consumers → retire old. Never break in place.

{ "name": "phone", "type": ["null","string"], "default": null }   // Avro: safe add
@JsonIgnoreProperties(ignoreUnknown = true)                        // tolerant reader
producer.value-serializer: KafkaAvroSerializer                     // + schema.registry.url
