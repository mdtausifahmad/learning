Delivery Guarantees — Cheat Sheet

Compressed from Lesson 05•Print-friendly

The one question

Everything reduces to this

Commit the offset BEFORE the work → at-most-once (can lose).
Commit AFTER the work → at-least-once (can duplicate).
You can’t make "do the work" and "commit" atomic for free — so you pick which failure you tolerate.

The three semantics

SemanticFails byCostUse when
At-most-onceLost messagesCheapestLoss OK: metrics, logs, telemetry
At-least-onceDuplicatesNeeds idempotencyDefault for almost everything
Exactly-once (effectively)Complexity/throughputDedup or transactionsMoney, inventory, dup = bug

Exactly-once, honestly

Exactly-once delivery ≈ impossible. Exactly-once processing ("effectively-once") is achievable via two routes:

  • Route A — at-least-once + idempotent consumer. For external side effects (DB, email, payment). Dedup on a stable id, or use a naturally idempotent upsert.
  • Route B — Kafka EOS. Only for read-process-write inside Kafka: idempotent producer (PID + sequence #) + transactions + read_committed.
Boundary rule

Kafka EOS stops at Kafka's edge. Any external side effect → back to at-least-once + idempotency. A Kafka transaction can't un-charge a credit card.

Idempotent consumer (Route A)

@KafkaListener(topics = ["order.events"], groupId = "payments")
@Transactional                                  // dedup mark + side effect in ONE db tx
fun on(rec: ConsumerRecord<String, OrderPlaced>, ack: Acknowledgment) {
    val id = ProcessedId("payments", rec.key())
    if (processed.existsById(id)) { ack.acknowledge(); return }   // duplicate -> skip
    payments.charge(rec.value())                // real side effect
    processed.save(ProcessedMessage(id))        // mark done atomically
    ack.acknowledge()                           // advance offset last
}

Unique PK on the processed-messages table = the backstop against racing duplicates.

Kafka EOS config (Route B)

producer: { acks: all, transaction-id-prefix: tx-, properties: { enable.idempotence: true } }
consumer: { isolation-level: read_committed }
Both hops

Guarantees exist producer→broker (retry after lost ack = dup) AND broker→consumer (commit order). Reason about both.
