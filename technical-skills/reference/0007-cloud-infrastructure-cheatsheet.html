Cloud Infrastructure Cheat Sheet

Mindset

Not “can we scale?” but “what scale and resilience does the business justify right now?” Choose boring, run less, and treat cost, RTO and RPO as design constraints.

Kubernetes vocabulary: Pod (smallest unit) · Deployment (desired replicas, rollout) · Service (stable identity, LB) · Ingress (external routing) · control plane · node.

Skip Kubernetes when…
  • The team lacks operating experience and no managed platform exists.
  • You run a few simple services, or serverless / PaaS already fits.
  • The bottleneck is product discovery, not infrastructure flexibility.
  • Nobody will fund platform ownership: upgrades, security, observability.

Infrastructure as Code

  • Code → review → plan → apply → drift detection; no console clicks.
  • Immutable infrastructure — replace images and instances, don’t mutate them.
  • Reusable modules across separated environments.
  • Secrets out of state and source control; policy checks on risky changes.
  • Tags for owner, service, environment, cost centre.

Deployment strategies

StrategyHowBest for
RollingReplace instances graduallyRoutine, low-risk releases
Blue-greenTwo environments; switch trafficFast rollback, major changes
CanarySmall % of traffic firstRisky changes with clear health signals
Feature flagsDecouple deploy from releaseGradual exposure, experiments

Define “healthy” before launch: error rate, latency, saturation, conversion, queue depth, rollback triggers.

Well-Architected pillars (review prompts)

PillarAsk
Operational ExcellenceCan we run, observe, change and improve it safely?
SecurityIdentity, data protection, detection and response built in?
ReliabilityCorrect under load, and recovers from failure?

Cost OptimizationSpending intentionally; waste removed?
SustainabilityUnnecessary consumption reduced?

Failure domains & recovery

TermMeaning
Availability Zone / RegionIsolated zone inside a region / geographic group of zones
Multi-AZ / Multi-regionSurvive one zone / one region (or serve global latency)
RTOMaximum acceptable downtime
RPOMaximum acceptable data loss

DR plan = owner, triggers, communication, RTO, RPO, verification steps. Backups don’t count until a restore is tested.

FinOps

  • Watch the drivers — overprovisioned compute, unbounded telemetry retention, cross-region and egress transfer, idle dev environments, premium services without a value case.
  • Unit economics (cost per request, tenant, order), not just the total bill.
  • Budgets and anomaly alerts; right-size from measurements.
  • Reserved capacity only for stable baseline; cost impact in every design doc.

Staff heuristics

  • Choose boring technology — spend innovation tokens only where novelty is essential, with an owner and exit plan.
  • Run less software — every self-run component is a security, upgrade, paging and continuity obligation.
  • The question isn’t “can we build it?” but “should the organisation own it?”
Traps
  • Multi-region before product and traffic justify it.
  • Kubernetes as a default rather than an operational commitment.
  • Manual console changes that bypass review and drift detection.
  • Autoscaling hiding inefficient code or a missing capacity model.
  • Ignoring data-transfer, observability and idle-resource costs.
