Architecture Trade-offs Cheat Sheet

Compressed from Lesson 03•Print-friendly
Mindset

Architecture is the important stuff — the hard-to-change decisions and the shared understanding behind them. Rank the qualities, say which ones you sacrifice, and keep the system changeable.

Architecture characteristics (pick, rank, sacrifice)

CharacteristicMeansUsual cost
ScalabilityHandles growth in load dimensionsMore distributed complexity
AvailabilityKeeps serving despite faultsWeaker consistency or higher cost
EvolvabilityAdapts to changing needsAbstraction and governance
TestabilityBehaviour verifiable cheaplySeams and design discipline
SecurityProtects data and operationsFriction, constraints, specialist review
OperabilityRuns safely in productionTooling and process investment

Internal quality is not gold-plating: with continuous change, it pays back in delivery speed within weeks.

Coupling types

  • Runtime — A must call B synchronously to work.
  • Data — components share tables or formats.
  • Semantic — one component knows another’s business rules.
  • Temporal — strict time sequence between systems.
  • Deployment — must be released together.
  • Conway’s Law — design mirrors communication structure; design teams and architecture together.

Granularity: forces

Disintegrators (split)Integrators (merge)
Different scalability needsShared transactions
Different change cadence / volatilityShared invariants
Security boundaryQuery needs across the data
Team ownershipLatency budget
Fault isolationWorkflow simplicity

Data ownership is the real boundary: one owner writes; others consume behaviour or events, never tables.

Saga checklist

  • Local commits + compensations — not magic rollback; some steps cannot be undone.
  • Visible intermediate states (e.g. PENDING order) that users and support understand.
  • Idempotent steps and retries with timeouts.
  • Operator repair path for stuck or half-compensated flows.

Migration patterns

PatternUse whenKey risk
Strangler FigReplace legacy capabilities gradually behind a routing facadeRouting and data synchronisation
Branch by abstractionSwap internals behind stable call sites, no long-lived branchLeaky abstraction, dual maintenance
Parallel runCorrectness matters; compare old vs new outputsComparison noise, double cost

Fitness functions (automated architecture rules)

  • Forbidden-dependency rules in CI.
  • Every API publishes an OpenAPI spec; event schemas pass compatibility checks.
  • Ownership metadata required per service.
  • Deploy gates on latency budgets, SLOs or cost guardrails.
  • Humans for judgment — not a late-stage review board that becomes a bottleneck.

Technical debt portfolio

TypeExampleSignal
Deliberate prudentManual process before product fitCheap now; repayment scheduled
Deliberate recklessNo migration plan for known scaleInterest exceeds benefit
AccidentalDesign no longer fits new needsRefactor as learning emerges
NeglectDependencies and tests decayRisk and change cost compound

Translate debt into business terms: delay cost, incident risk, opportunity cost, throughput, compliance exposure.

Traps
  • Microservices to fix what is really an organisational problem.
  • Shared databases while claiming independent deployment.
  • Maximising one quality and pretending the others are unaffected.
  • Sagas without idempotency, compensations or repair workflows.
  • Big-bang rewrites instead of incremental migration.
  • Governance that slows teams without improving decisions.
